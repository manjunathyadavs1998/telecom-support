## Confirmed OK (no finding)
- CSRF: the cookie is read at send time with no masking, which matches the plain `CsrfTokenRequestAttributeHandler` (`SecurityConfig.java:84-86`) and the rotation in `AuthController.rotateCsrfToken` on login and logout. `GET /auth/csrf` only reads the cookie and doesn't rotate it.
- `/me` shape, `Permission` and role enums are taken from the generated types. Login 400 field names (`username`, `password`) match the `LoginRequest` record. The 401 login detail matches `BAD_CREDENTIALS_DETAIL`. `Retry-After` is an integer number of seconds.
- Nav and landing for all 7 role combinations match the backend §3 matrix and the §3.1 seed users. The customer-only pairing excludes the agents correctly. Outbound gets Analytics through `analytics.read`.
- The UI is never the only guard. Slice 01 renders only ComingSoon placeholders with no data, and every `/api/**` endpoint is enforced server-side (`SecurityConfig.java:94`, `@PreAuthorize`).
- Design §12 F1 needs no security change: `anyRequest().permitAll()` (`SecurityConfig.java:95`) already lets SPA routes through. Design §12 F1 is necessary for ADR 0001 deep links and reload.
- Token contrast values meet WCAG AA as stated.
