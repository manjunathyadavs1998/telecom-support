## Summary
High 0 · Medium 2 · Low 13.

The payment flow holds up against the design:
- The idempotency key is path- and scope-aware.
- sessionStorage holds only `{key, bodyHash, reference, savedAt}`, and it is cleared on logout.
- The redirect allowlist refuses other origins, `//host`, `javascript:` and `data:`.
- Polling runs only while PENDING and inside the window, and a failed poll keeps the last status.
- Money is never handled as a float: `formatInr` formats a BigInt and copies the paise digits.

I found no XSS sinks, no hand-written DTOs and no Zustand server state. Every route has a forbidden-role test.

## Checked and OK (no finding)
- **Route guards:** every §2 route, child routes included, sits under `RequirePermission` with the parent's ∪ the child's permissions. `ParamGate` sends a malformed `:reference` to NotFound with no API call. IN001 gets the 403 page on all 10 routes with zero requests (`RequirePermission.test.tsx:226-310`).
- **Idempotency:** the key is the same for the same `{operation, path, body}` and different on another path. It is kept on 409/5xx/network and dropped on 400/404/422. A record survives a remount and is ignored after 24 h, in line with the server's 24 h key TTL (00-overview §7). Records go only to sessionStorage, nothing to localStorage.
- **Polling:** 3 s only while PENDING and the window is open. The 2-minute window has "Check again". Focus refetch stays on. A failed poll keeps the status with a notice and never shows FAILED. On a terminal state focus moves to the heading and the live region is left empty. The query string is ignored.
- **OTP:** `gcTime: 0` plus `reset()` in `finally` on both E3 and E4, and the code is never put in a toast. `attemptsRemaining` checks the type at runtime. There is a 30 s resend cooldown, a 429 countdown from `Retry-After`, and expiry is announced only at 1 minute and at 0.
- **Money and dates:** no float arithmetic anywhere. `isPositiveMoney` is a string check. Date-only values are formatted without a time zone. The range rules are 366 days and no future `to`, computed from today in IST.
- **Types:** API types are generated (`gen-api.mjs` adds `02-customer.ts`, including E6 `claimedSubscriptionIds`). No hand-written DTOs and no new Zustand store.
- **Rendering:** no `dangerouslySetInnerHTML`, and all server text renders as React text.
