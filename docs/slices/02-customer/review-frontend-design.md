## Notes (no finding)
- Staff gating: `userType CUSTOMER` is inherited by every child route, and IN001 (holds `plan.read`, `payment.read`) is tested on
  `/customer/payments/PAY-…` and `/customer/requests/new` (frontend.md:42-43, :221, :236). This matches 01 planner decision 1.
- Idempotency semantics follow 00-overview §7: non-2xx deletes the key, so "keep the key on 409/5xx, reset on 2xx" is correct.
- Erratum E1 (409 on PENDING **or** REVIEW) is reflected in the Pay bill 409 copy (frontend.md:140-141).
- No hand-written DTOs, no new Zustand store, and nothing in `localStorage`, so the CLAUDE.md frontend rules hold.
- Task list F1–F20: each task has ≤ ~5 files and the order is sound (types → helpers → primitives → routes → pages → dashboard → e2e).
  Gaps: `Breadcrumbs.tsx`/`NavList.tsx` (F9) and `playwright.config.ts` (F10) are in no task.
