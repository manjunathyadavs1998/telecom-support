## Verified without finding (for the record)

- **Race safety, commands:** each O6–O9 call is one `@Transactional` that starts with `SELECT … FOR UPDATE OF c` by unique reference (`CaseRepository` `LOCK_OUTBOUND`). That locking read is the first statement, so no stale snapshot. Then scope (404), 403/409/422, and the version-guarded UPDATE that must change exactly 1 row (else 409 `stale_version`). Activity, bookmark `last_seen_at` and audit are written in the same tx. N parallel claims serialise on the row lock, the losers read an owner and get 409 `already_assigned`, and the owner's retry is a no-op.
- **Auto-close job:** per-row `TransactionTemplate`. The guard `WHERE id AND status='RESOLVED' AND resolved_at <= :cutoff` writes activity and audit only when 1 row changes, so parallel runs and a concurrent reopen/close are safe. It takes no users lock (activity actor is null). The cutoff matches `CaseLifecycle.check` (`now ≥ resolved_at + window`). `ProfileGuard` refuses `-` under prod.
- **§3.1 table:** `CaseLifecycle.TABLE` matches the table exactly (REOPENED → IN_PROGRESS/PENDING_*/RESOLVED, RESOLVED → CLOSED/REOPENED, CLOSED → REOPENED, CREATED → none). R8 and R9 window edges are correct. Reopen clears the resolved/closed columns, does `reopen_count + 1`, and keeps owner and SLA. The CHECKs hold for every `TransitionValues` branch.
- **SQL safety:** every value is a named parameter. `QueueRepository.where` appends only fixed fragments, ORDER BY comes from the `Sort` enum, `FIELD(...)` is a constant, and `OutboundScope.SQL` is fixed. LIMIT/OFFSET are bound.
- **Scope S:** applied in O1/O2 SQL, O5, every command (`lock` → 404), O10, and the O12 row flag and `changedCount`. Actor id and team come only from `CurrentUser`.
- **PII:** the contact MSISDN is masked (`******` + last 4) in rows and detail, and the full number is shown only when `assignedUserId == actor.id()`. There is no email or address. The mobile filter is in the POST body, and the validator message never echoes it. No case PII is logged (the job logs only the reference).
- **Time:** all new reads use `getObject(…, LocalDateTime.class).toInstant(UTC)`, and writes use `LocalDateTime.ofInstant(…, UTC)` (PR #17). Date windows are Asia/Kolkata inclusive days → `[start, nextDayStart)`, ≤ 366 days, consistent with `CaseWindow`.
- **V11:** columns are added nullable or with a default, the backfill runs before the CHECKs, and the FK on `resolved_by_user_id` is nullable, so it is safe on populated data. The R__ seeds and test data set the new columns and are idempotent (`NOT EXISTS`). No merged migration was edited.
- **Audit (XC-06):** `CASE_ASSIGNED` (CLAIM/REASSIGN with from/to user and team, reason, status from/to) and `CASE_STATUS_CHANGED` (from, to, remarks, closureType, source request|auto_close, job actor null). Notes and bookmarks are not audited, by design.
- **Authz:** every O1–O13 handler has `@PreAuthorize(case.read.queue [+ perm])` as §5. O9 adds R10's service checks. Service 403s go through `GlobalExceptionHandler` → `DeniedAccessRecorder`.
- **Contract:** record and JSON names match `openapi.yaml` (`new`, `case`, `maskedMsisdn`, `CaseActivity.type/note/at`, `AllowedActions`, `BookmarkPage.changedCount`), as do the `CaseProblem.reason` values and statuses (201 O9, 204 O10/O11/O13).
- **03 I10:** `CaseTimelineAssembler` keeps non-id values unchanged and maps only ASSIGNED ids to names, and actor names are unchanged. No regression found (see #8 for a performance nit).
- **Known deviations, judged sound:** (a) service 403s record reason `permission`. The recorder only distinguishes csrf, verification_required and permission, and the client sees the same `forbidden` either way. Recommend a one-line design erratum replacing `not_owner` in §4/§7. (b) The idempotent replay has the same content with a different key order, as 02/03 do. (c) `changedCount` scoped to S matches the rows' `changed`, which is false for inaccessible rows.
- **Traceability:** slice 04 rows moved to Built with components. Deferred ITs are listed in test-plan §3.4.
