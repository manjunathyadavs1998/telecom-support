## Checked and fine
- Every I1–I15 has `customer.lookup` + a §8 permission. Every endpoint has a forbidden-role case for CUSTOMER, OUTBOUND_AGENT,
  OUTBOUND_SUPERVISOR, BUSINESS_ANALYST and BUSINESS_AUDITOR, plus INBOUND_AGENT without REACTIVATION_APPROVER on I13/I14 (§9 `InboundAuthzIT`).
  This matches the V2 seed (`customer.lookup` only on INBOUND_AGENT).
- Agent binding of checks (agent from `ActorProvider`, other agent's check → 404, 30 min not extended), OTP confirm reusing 02 §3.2,
  codes/answers never stored, audited or logged.
- Reactivation: guarded transitions with a single writer, provider calls outside the tx, the open-request UK cannot collide with a
  transition (only one open row per account, so the 02 E1 mistake is not repeated), the DB CHECK forbids prohibited-eligible rows and the code
  hard-codes the prohibition too, 24 h CHECK, audit for every transition, outbox in the same tx.
- Idempotency: path-aware hash (02 D6) for I12/I14 with a mismatch test. 503 → key released (matches `IdempotencyService`).
