# ADR 0002 — Spring JDBC with named parameters; no JPA/Hibernate

- Status: Accepted · Date: 2026-11-24 · Decided by: product owner

## Context
The product owner requires that SQL is explicit and reviewable, and that it is not generated by Hibernate. Case assignment, analytics aggregates and bounded date-range queries need precise SQL (atomic `UPDATE … WHERE assigned_to IS NULL`, `GROUP BY` over dates).

## Decision
- Use `spring-boot-starter-jdbc` with `NamedParameterJdbcTemplate`. Hand-written SQL lives in repository text blocks.
- No `spring-boot-starter-data-jpa`, Hibernate, `JpaRepository` or `@Query`. No `jakarta.persistence` imports.
- Flyway owns the schema. Migrations are immutable once committed.
- Dynamic filters are built from fixed SQL fragments with bound parameters. Sort keys go through a whitelist.

## Consequences
- Every query is visible in code review and can be tuned with `EXPLAIN`.
- More boilerplate (row mappers). Once the first endpoint pattern is approved and green, it is captured as a project skill.
- The rule is enforced by an ArchUnit test (`ArchitectureTest`, slice 01) and by review, not only by this document.
- Reviewed 2026-11-24 for the clean start: decision unchanged.
