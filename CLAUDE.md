# Telecom Customer Support — project memory for Claude

AI-native project: **all code is generated by Claude**. Requirements live in `docs/brd/brd.md`.
Every change must trace to a BRD ID (CUS-xx, INB-xx, OUT-xx, BUS-xx, BR-xx, XC-xx, NFR-xx).
`docs/requirements/traceability.md` is the single source of truth for coverage — update it with every feature.

## Architecture (see docs/adr/)
- **Monolith**: one Spring Boot JAR serves the REST API (`/api/**`) and the built React SPA (everything else).
- `backend/` Java 21, Spring Boot 3.5, Maven Wrapper (`backend/mvnw`), MySQL 8, Flyway.
- `frontend/` React + TypeScript + Vite + Tailwind + shadcn/ui, TanStack Query/Table, Zustand, RHF + Zod, Recharts.
- `docker-compose.yml` runs MySQL (3306), Mailpit (SMTP 1025, UI 8025) and the app (8080).

## Non-negotiable rules
1. **No JPA / Hibernate / Spring Data repositories.** Data access is Spring JDBC only:
   `NamedParameterJdbcTemplate` + hand-written SQL with named parameters (`:name`) in Java text blocks,
   `RowMapper` → Java `record`. Never build SQL by string concatenation of values. Dynamic WHERE clauses
   are assembled from fixed fragments with parameters bound via `MapSqlParameterSource`.
2. **Schema changes only via new Flyway migrations** `backend/src/main/resources/db/migration/V<n>__<desc>.sql`.
   Never edit a migration that has been committed. Dev/demo data lives in `db/seed` (dev profile only).
3. **Authorization is server-side** (BR-10): every endpoint has `@PreAuthorize` with a permission from BRD §8
   (`case.create`, `case.assign`, …) and services enforce record scope. A customer's account id always comes from
   the authenticated principal, never from the request body/path.
4. Errors are RFC 7807 `ProblemDetail`; every response carries `X-Correlation-Id`.
5. High-risk actions (payment, reactivation, status change, assignment, profile change, export) write an `audit_events` row.
6. Create/payment/reactivation endpoints honour the `Idempotency-Key` header (NFR-REL).
7. Lists are server-side paginated with bounded date filters; default window is 3 months (BR-05/06).
8. Times are stored in UTC (`DATETIME(6)`), displayed in `Asia/Kolkata`.
9. Never log secrets, OTPs (except the dev mail sink), passwords or full card data. Mask PII where not needed (OUT-04.4).
10. Frontend: server state only in TanStack Query; Zustand only for session/UI. Every screen has loading, empty,
    error and validation states (XC-03). API types come from the generated OpenAPI file — do not hand-write DTO types.

## Commands
| Task | Command (run from repo root) |
|---|---|
| Start MySQL + Mailpit | `docker compose up -d mysql mailpit` |
| Backend run (dev) | `cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev` |
| Backend tests | `cd backend && ./mvnw verify` (uses Testcontainers → Docker must be running) |
| Frontend dev | `cd frontend && npm run dev` (proxies `/api` to :8080) |
| Frontend checks | `cd frontend && npm run lint && npm run typecheck && npm test` |
| Regenerate API types | `cd frontend && npm run gen:api` (backend must be running) |
| Single JAR | `cd backend && ./mvnw -Pfrontend package` → `target/support.jar` |
| Full stack | `docker compose up --build` |

**Windows host note:** this workstation's Application Control policy blocks unsigned native npm binaries
(`rolldown`, `oxlint`). Run frontend tooling in the Linux container instead (same image as CI):
`docker compose run --rm -T web sh -c "npm ci && npm run typecheck && npm run lint && npm test"`.
Never "fix" this by downgrading tools or deleting lockfiles.

## Definition of done (per story)
- Code + Flyway migration + seed (if needed) + OpenAPI-typed client + UI states.
- Backend tests: service unit tests and at least one MockMvc/Testcontainers test incl. a **forbidden-role** case.
- Frontend: component test for the main form/list; Playwright journey updated when a user flow changes.
- `traceability.md` row updated (BRD ID → code paths → tests). `docs/ai-journey/` note for the branch.
